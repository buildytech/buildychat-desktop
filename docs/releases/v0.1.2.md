BuildY Chat desktop 0.1.2, with the web app from `buildytech/chat` at `b3e0794`.

- **The page preview opens.** "Open in new window" gave `http://wails.localhost/home?preview&session=…` and nothing loaded: `window.open` in a Wails webview makes a popup that has no asset handler for `wails.localhost` (WebView2) or none at all (WebKit). The host now opens the preview in a second app window on the same asset server and storage (`POST /runtime/v1/preview-window`, only an in-app preview address; one window per session, raised on a second click). The headless build and the web app keep using the browser's own window.
- **Every Brand Skin has both light and dark.** A skin used to carry the palette of one mode only (inline on the page, with the mode fixed), so TITAN was dark only and a later "Lumen" light only. The palette is now written as one rule per mode, the light/dark switch picks one, the validator requires both modes and checks WCAG AA in each, and the brand contract's dark colours are no longer empty. Skins made before this show both modes too. The Design prompt asks for both.
- **Design edits a skin instead of making a new one each time.** The Design panel shows "Editing «name», revision N": your next message changes that skin (the active one by default; pick another with **Edit**), the model gets its current brief and theme, and the skin keeps its id with the next revision. **Create new** starts a fresh skin. **Apply in Design** under an Ask answer edits the active skin.
